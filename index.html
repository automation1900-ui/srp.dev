About

Where engineering discipline meets design obsession

I don't just write code that works — I write code that feels considered, fast and beautiful.

Programming is my craft, not a checkbox.

Every interface starts as a system: semantic HTML for meaning, a token-driven CSS layer for consistency, typed JavaScript for confidence, and a component structure that scales without turning messy.

Then comes the part most people skip — feel. Scroll rhythm, hover states that respond in under 100ms, ripple feedback on every tap, glass layers that blur instead of block, and 3D that renders only when it's on screen.

Performance is a design decision, not a clean-up task. I budget animation work to transform and opacity so the compositor handles it, cap device pixel ratio on retina phones, pause WebGL when it scrolls out of view, and respect prefers-reduced-motion for anyone who asks for calm.

Code Philosophy

Too much care? There's no such thing.

A few beliefs that shape every line I ship.

“

Readable code is a gift to the next developer — often future me at 2am. I name things honestly, keep functions small and let the structure explain itself before a comment has to.

Clarity over cleverness
“

Animation should never make a phone sweat. I animate transforms and opacity, avoid layout thrash, throttle pointer effects and let the browser's compositor do the heavy lifting.

Frame budget first
“

Design is not decoration. Spacing, contrast, type scale and motion are a language — and every element either builds trust or quietly erodes it.

Details are the product
“

If it breaks on a low-end Android with a slow connection, it isn't finished. Mobile-first isn't a slogan; it's where the real testing happens.
